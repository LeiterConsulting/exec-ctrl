## Objective

Make self-hosting and method evolution a first-class exec-ctrl pattern so the repository does not merely demonstrate recursive use incidentally through repo-specific records, but teaches it explicitly and repeatably.

## Requirement Definitions

| ID | Requirement | Definition | Success Signal |
| --- | --- | --- | --- |
| `MSH-1` | Self-hosting method guidance | The repo should explain how exec-ctrl governs its own improvement work. | A dedicated generic guide exists for self-hosting and method evolution. |
| `MSH-2` | Reusable activation surface | Future users should be able to invoke method-improvement work with the same ease as other task shapes. | A ready-to-copy prompt or equivalent workspace-guidance surface exists for method-evolution initiatives. |
| `MSH-3` | Discoverable integration | The main method and bootstrap docs should route users to the self-hosting pattern rather than leaving it implied only in repo-local artifacts. | README, method docs, cookbook, and other relevant entry docs reference the self-hosting path coherently. |

## Scope In

- generic self-hosting and method-evolution guidance
- reusable prompt or template surfaces for method-improvement work
- entry-doc refinements that make the pattern discoverable
- self-governing exec-ctrl records for this enhancement

## Scope Out

- runtime automation that enforces the method mechanically
- major redesign of project-pack or initiative-pack fundamentals
- product-specific case studies from unrelated repositories

## Deliverables

1. a generic self-hosting and method-evolution guide
2. a reusable activation surface for method-improvement work
3. updated entry docs that expose the self-hosting pattern
4. a self-governing initiative pack for this enhancement

## Must-Pass Success Criteria

1. the repo contains a dedicated generic guide for self-hosting and method evolution
2. the repo contains a ready-to-copy prompt or equivalent activation surface for method-improvement work
3. the main method docs route users to the self-hosting pattern clearly
4. this enhancement is governed under initiative-mode exec-ctrl within the repo

## Should-Pass Success Criteria

1. the self-hosting guidance stays generic rather than tied only to this repository
2. the method-evolution workflow is concrete enough to use without extra interpretation
3. the new surfaces fit the existing repo structure instead of creating a parallel system

## Non-Goals

- replace the existing bootstrap workflow
- create runtime tooling that mutates docs automatically
- recast every existing example around self-hosting work

## Completion Conditions

- all must-pass criteria are satisfied
- the new guidance, prompts, and entry-doc links are coherent
- deferred future ideas remain explicit rather than implied complete

## Baseline Evidence

## Risks and Dependencies

1. self-hosting guidance could drift into repo-specific narrative instead of remaining generic
2. too much meta-process language could reduce the repo's usability for ordinary bounded initiatives
3. the self-hosting pattern must reinforce, not bypass, the existing authority and evidence rules
